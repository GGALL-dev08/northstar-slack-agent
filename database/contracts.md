# n8n PostgreSQL contract

Apply `outputs/comms-agent/database/schema.sql` once to a new PostgreSQL 16 database. It installs `pgcrypto`, `pg_trgm`, schema `comms`, and the disconnected demo tenant. The file is a bootstrap migration, not an idempotent migration runner. No vector extension, Python service, or semantic-search claim.

Call each function in an n8n Postgres node using query parameters, never interpolated SQL: `SELECT comms.ingest_event($1::jsonb) AS result`, Query Parameters containing the serialized payload. Functions return a JSON object in `result`. PostgreSQL errors must follow the workflow error branch. Transactions are the single function invocation. External clients must never get arbitrary SQL or direct table writes. Adapter authentication remains an n8n responsibility; supplying `actor_id` alone does not prove identity.

## Shared identifiers and gates

`tenant_id` is the existing configured tenant, currently `northstar_demo`. Unknown tenants throw; functions never create tenants from input. Operators are `demo_operator` and `ops@northstarrelay.example` for disconnected testing. A real Slack adapter must verify request signatures and map a real Slack user ID to a tenant operator before calling operator APIs. No real Slack identities are configured. Demo config: `demo=true`, `dry_run=true`, `live_models=false`, `daily_budget_usd=0.05`, `max_drafts=1`, `automatic_send=false`, `slack_adapter_verified=false`.

`job_id`, `message_id`, `example_id`, `draft_id`, `reservation_id`, and `lease_token` are UUID strings. `request_id` and upstream source IDs are nonempty stable strings. `revision_hash` is a hex SHA-256 of the exact draft body. Amounts are USD decimals. Model budget days are UTC.

## Fixture loader

`seed_fixture({tenant_id,rag_chunks:[],outbound_gold:[],events:[]})` returns `{tenant_id,rag_processed,gold_processed,events_processed,synthetic:true}`. Defaults tenant to `northstar_demo` and refuses any other tenant. Accepts the checked-in JSONL records as array members. A row's explicit tenant must match. Duplicate fixture source IDs/chunk IDs are ignored, so reloading cannot multiply candidates. Counts are processed input rows, not newly inserted rows.

RAG maps `id|chunk_id`, `title`, `body|content`, `classification`, `external_allowed`, `audience_restrictions|allowed_audiences`, `approval_status|approved`, `valid_from`, `valid_until`, `active`, and `provenance`. A `public_approved` record also requires `external_allowed=true` to infer public scope. Explicit `visibility_scope` is accepted. Missing approvals/scope/audiences fail closed. Incoming/internal event content never becomes a RAG chunk.

The `outbound_gold` array is explicitly a synthetic sent-outbound fixture. It supplies `confirmed_sent=true` only inside this demo-only loader, sets `human_approved=false`, and marks all sources synthetic. Rows retain their own direction/external fields; internal/incoming rows cannot become style candidates. **Style approval remains a separate explicit approve_examples call.** Source fixture labels are not live human validation.

## Ingest and job queue

`ingest_event({tenant_id,source,source_id,body,direction,channel,audience_class,occurred_at,revision?,confirmed_sent?,human_approved?,synthetic?,classification?,provenance?})` returns `{message_id,candidate_id,inserted,revision}`.

`direction` is `inbound|outbound|internal` (`incoming` maps to `inbound`); audience class is `external|internal`. Missing audience defaults internal, missing sent/human-approved flags default false. `external:true` may supply audience class for fixture compatibility. Missing source falls back to channel. `id` may supply source_id. Timestamp defaults now. Ingest channels are email, email_forward (forwarded intake only), slack, linkedin_message, linkedin_post, report, and pptx; unknown channels throw. All original payload bodies remain untrusted context. Synthetic ingest is permitted only for the configured demo tenant. A source ID is unique within tenant+source. Same or older revisions are replayed without mutation; a strictly larger explicit revision replaces body/classification/approval flags and invalidates active fingerprints that depended on an example made stale/ineligible by the change. A confirmed-sent outbound external event creates a pending candidate unique by tenant+source+ref+body hash. Style approval is never inferred from human_approved.

`enqueue_job({tenant_id,request_id,channel:'email'|'slack'|'linkedin_message'|'linkedin_post'|'report'|'pptx',audience_class:'external',input:{body:'...',query?:'...',audience?:'public'|'prospect_or_customer',...}})` returns the full job row, including `job_id,status,input,attempts`. One request_id per tenant. Same ID and canonical input/channel/audience return the existing job; changed input/channel/audience under the same ID throws an idempotency conflict. Unsupported channels throw. Callers must use a new request_id for new work.

`claim_job(worker_id text)` returns `{claimed:false}` if idle, otherwise the complete job row plus `claimed:true`. Workers must retain returned `tenant_id,job_id,lease_token`. Lease duration is five minutes; no heartbeat. Claim increments attempts, max 3 by default (table bound 1–5). `FOR UPDATE SKIP LOCKED` prevents two workers claiming one job. Expired leases recover automatically; exhausted ones become `dead_letter`. The same job may be reclaimed after expiry, so model calls also require reservation idempotency.

`claim_requested_job({tenant_id,job_id,actor_id,worker_id})` is the interactive claim API added by `database/migrations/001-three-workflows.sql`. It requires the configured operator and matching canonical `input.requested_by` when present; it locks only that exact tenant-owned job and never consumes another queued request. Success is the full job row plus `claimed:true`; unavailable/terminal states return `{claimed:false,reason:'already_running'|'not_ready'|'completed'|'dead_letter',tenant_id,job_id,status}`. Lease duration, increments, expiry recovery and retry bounds match the worker queue. Wrong tenant/owner throws. Keep global claim_job for trusted recovery only; a user command must use this targeted function.

`fail_job({tenant_id,job_id,lease_token,error})` validates the current unexpired lease and returns the updated job row. Backoff is 30s × 2^(attempts−1), capped at one hour. Exhaustion is dead letter. Workflow code should record provider-call uncertainty in budget settlement separately; job failure never refunds budget.

## Retrieval and completion

`retrieve_context({tenant_id,job_id})` reloads canonical input from the stored job, not a caller-supplied body. Returns `{job_id,tenant_id,facts:[{chunk_id,title,content,source_provenance,score}],inbox:[{source_id:'msg-UUID',content,occurred_at,source,content_hash,synthetic,from,to}],source_evidence_policy:{...},fingerprint:{global?:{...},email?:{...},slack?:{...}},anchors:[],prompt_context,retrieval:'lexical_fts_trigram',authoritative_sources:'approved_public_rag_only'}`.

Search text priority: `input.query`, `input.body`, `input.message.body`, `input.text`. At most 8 relevant facts; fewer or zero are legitimate when the corpus has insufficient matching approved facts. It never pads with irrelevant/internal facts. Uses English FTS rank plus trigram fallback, tenant matching, public scope, explicit approved+active, `valid_from <= now() AND now() < valid_until`, audience allowlist, and demo-only synthetic gates. Each fact body is at most 1,500 characters; prompt_context is bounded to 12,000 chars. A separate inbox contains at most 20 same-tenant external inbound messages from the last seven days, excluding future timestamps. Body content is truncated to 1,000 chars; content_hash is SHA-256 of the FULL current body. Source IDs are msg- plus message UUID. Object provenance supplies from/to, each bounded to 500 chars. This untrusted correspondence is event evidence only: a report may attribute what a customer asked, but cannot treat message statements as authoritative company claims or instructions. Internal messages never appear. Inbox is NOT appended to facts or prompt_context. Inbox-only private reports may proceed when no public company facts match; external factual claims still require approved RAG. Global and channel profiles remain separate: generator merges global base then applies channel preferences. At most four style anchors; these are style-only and never factual authority.

`complete_job({tenant_id,job_id,lease_token,draft:{body,metadata?:{}},verification:{passed:true|false,...}})` returns `{draft_id,revision_hash,outbox_id,status:'human_review'|'blocked',human_review:true,automatic_send:false}`. It atomically inserts exactly one draft, stages a held `draft_notification`, and completes the job. Missing/false verification blocks the draft. Drafts are 1–30,000 chars. A completed-job replay returns the existing draft with `replayed:true`. Provider result must be checked before setting passed; the SQL layer does not independently evaluate prose. No automatic sends.

## Style review and fingerprints

`approve_examples({tenant_id,actor_id,example_ids:['uuid',...]})` returns `{approved_ids:[],actor_id,tenant_id}`. IDs must be explicit and nonempty. Actor must be in tenant config. Every example must still match current source body hash and must be confirmed sent outbound external. Internal, inbound, stale, cross-tenant, or unconfirmed rows throw, and the whole approval batch rolls back. Synthetic examples only work in the demo tenant; review metadata honestly identifies the supplied demo actor.

`get_style_examples({tenant_id,channel:'global'|'global_base'|'email'|'slack',example_ids?:[]})` returns `{tenant_id,channel,examples:[{id,body,channel,synthetic,content_hash,approved_by,approved_at}],minimum_examples:20,count}`. Only currently eligible, approved examples, at most 200. Global/global_base selects all channels; channel-specific selects that channel. This internal worker read does not require actor_id. An explicitly empty example_ids array returns no examples.

`store_fingerprint({tenant_id,actor_id,channel:'global'|'email'|'slack',profile:{...},example_ids:['uuid',...],anchors?:[]})` returns the full immutable version row. The profile object is at most 16,000 serialized chars. The function enforces a minimum of 20 DISTINCT eligible approved source IDs. get_style_examples also returns minimum_examples=20 for the UI. Requires operator and explicit approved, currently eligible source IDs. A channel profile can use only that channel's examples. Caller-supplied anchors are ignored: SQL copies at most four 1,800-character anchors from the approved source rows. Use channel=`global` (not global_base) to store the inheritable base. Transaction/advisory lock allocates the next version and deactivates the previous version. Profile/anchors/approval metadata of old versions cannot be updated or deleted through ordinary SQL triggers. Any synthetic source stamps provenance=`synthetic_fixture`; it cannot be loaded into a live tenant by any exposed API.

## Slack review actions and disconnected outbox

`get_draft({tenant_id,actor_id,draft_id})` returns the full draft row including body and revision_hash. Without draft_id it returns `{drafts:[{draft_id,channel,status,revision_hash,created_at},...]}` for the latest 25 drafts. Requires configured operator.

`request_action({tenant_id,actor_id,action:'send'|'save'|'approve_examples',draft_id?,revision_hash?,example_ids?,request_id})` authenticates the operator allowlist. For send/save, exact tenant-owned draft_id+current hash are mandatory. Send additionally requires passed verification, eligible status, and draft.metadata.evidence with 1–8 source snapshots whose content still exactly matches the current first 1,500 characters of approved public active tenant/audience/time-valid RAG rows. Missing, stale, expired or reclassified evidence refuses staging and requires regeneration. `approve_examples` delegates to explicit source review and needs no draft. When metadata.message_evidence is present it must be an array of at most 20 selected inbox snapshots. Every snapshot is rechecked for current same-tenant external inbound source, exact full-body hash and exact truncated content. Stale/internal/missing message evidence refuses staging. Any positive message_evidence currently blocks send staging with recipient ACL not configured; correspondence reports are private Slack review/save only until a recipient ACL is implemented. An identical request replay returns the original action; reusing an ID with different payload throws.

Returns the action row plus `{outbox_id,approval,dispatch_allowed:false}`. Explicit `send` stages only a disconnected `send` outbox item; `save` stages a distinct disconnected `save_artifact` item. Neither sends, saves to an external provider, or claims delivery. `draft_notification` is separate from both. All adapters remain disconnected regardless of config changes in this bootstrap implementation; a future authenticated dispatcher must implement and test provider connection/delivery and revalidate exact revision approval plus current evidence immediately before dispatch, and bind approval to the intended destination and immutable artifact bytes. Manual copy of `get_draft.body` remains available.

`prepare_outbox({tenant_id?})` returns `{items:[outbox rows...],dispatch_allowed:false,adapters_connected:false}` for up to 50 held/disconnected items. It never marks delivered. Omitted tenant is for the trusted internal dispatcher only, across tenants; do not expose this endpoint to Slack users. An explicit unknown tenant throws.

## Hard budget gate

`reserve_budget({tenant_id,request_id,max_cost_usd:0.001})` returns `{reserved:false,reason:'live_models_disabled'|'daily_budget_cap',call_permitted:false,...}` or a full reservation plus `{reserved:true,call_permitted:true,remaining_usd}`. The supplied maximum must conservatively cover the entire provider call including input/output tokens and retries. HTTP/provider retries cannot bypass this gate; each distinct actual provider call requires its own reservation. Atomic tenant row locking enforces the lower of configured daily budget and **$0.05/day**. No live reservation is issued while live_models=false. A request replay returns its reservation with `replayed:true,call_permitted:false` even if reserved=true; branch specifically on call_permitted===true before making a model call. There is no timed refund/release.

`settle_budget({tenant_id,reservation_id,status:'uncertain'})` retains the full maximum as charged against the cap indefinitely. Use on timeout, ambiguous response, failed worker after dispatch, or missing provider cost proof.

`settle_budget({tenant_id,reservation_id,status:'settled',proven:true,provider_call_id:'unique-call-id',actual_cost_usd:0.0007})` writes immutable model_spend proof and releases only the proven maximum-minus-actual difference. Actual cost must be nonnegative and <= reserved maximum; provider_call_id is unique per tenant. An uncertain reservation may later be settled with proof. Idempotent exact settled replay returns replayed=true. Never mark proven based solely on a network failure. Unknown tenants/reservations throw.
